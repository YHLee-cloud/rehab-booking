# 復健科自費療程預約系統

一個提供三種自費療程（SIS超磁場治療、徒手治療、體外震波治療）視覺化排程、報到與治療完成紀錄、月業績報表匯出、以及內部維護介面的預約系統原型。

## 功能總覽

1. **視覺化排程**：三種療程分頁切換，以「時間」為列的單欄時刻表，一眼看出空檔。點擊空格即可開單，系統會自動檢核「同一位執行人員同時段是否已有其他預約」，衝突時會擋下並顯示衝突對象。
2. **報到與完成治療**：「報到 / 完成治療」頁面列出當日所有預約，操作人員可一鍵標記「報到成功」與「完成治療」，系統會自動記錄實際時間戳記。
3. **月業績報表**：依年月彙總「已完成治療」的營收與人次，並可依療程項目 / 執行人員 / 開單醫師分別彙總，一鍵匯出 CSV（可直接用 Excel 開啟，含中文不亂碼）。
4. **遠端多裝置存取**：純網頁架構，部署到雲端後，診所內任何手機、平板、電腦只要開瀏覽器登入即可操作，無需安裝軟體（詳見下方部署建議）。
5. **內部維護介面**：可新增/停用開單醫師、執行人員名單，以及新增/修改自費療程項目（名稱、代碼、價格、時長、顏色）。

## 技術架構

- 後端：Node.js + Express（純 JavaScript，無需編譯建置）
- 前端：原生 HTML / CSS / JavaScript（無框架、無建置流程，載入快、好維護）
- 資料儲存：目前採 JSON 檔案（`data/db.json`），足以應付中小型診所單機示範與小量並發使用；正式上線建議依下方「進階：升級為正式資料庫」章節升級為 PostgreSQL，取得更穩固的多人同時寫入與雲端自動備份能力
- 身分驗證：帳號密碼登入 + 伺服器端 session（密碼以 scrypt 雜湊儲存，不存明碼）

## 本機執行

```bash
cd rehab-booking
npm install
npm start
```

啟動後開啟瀏覽器至 `http://localhost:3000`。

**預設管理者帳號**：`admin` ／ 密碼：`admin123`
👉 請務必在「內部維護 → 帳號設定」立即修改密碼。

種子資料已內建 3 位範例醫師、6 位範例執行人員、3 項療程，可在「內部維護」頁面直接修改成貴診所實際名單。

## 部署到雲端，讓不同手機/電腦都能遠端存取

你目前沒有既有的雲端環境，以下是兩種建議方案，依需求選擇：

### 方案 A（推薦，最快上線）：Zeabur 或 Render 一鍵部署

適合現況（中型診所、單機 JSON 檔案資料庫也夠用），步驟：

1. 將此專案上傳到一個 GitHub 私有倉庫（Zeabur / Render 都支援直接從 GitHub 部署）。
2. 到 [Zeabur](https://zeabur.com)（台灣團隊開發，介面中文、對 Node.js 很友善）或 [Render](https://render.com) 建立新的 Web Service，選擇這個倉庫。
3. Build 指令：`npm install`；Start 指令：`npm start`；Port 使用環境變數 `PORT`（程式已支援）。
4. **重要**：務必替 `data/` 資料夾掛載「持久化磁碟（Persistent Volume / Disk）」，否則平台重新部署時 JSON 資料庫會被清空。Zeabur 與 Render 都有提供此功能（Render 稱為 "Disks"）。
5. 部署完成後會取得一個 `https://your-app.zeabur.app`（或 render.com）網址，診所內任何手機、電腦連上網路，用瀏覽器打開這個網址、登入帳號密碼即可操作，天生支援多裝置同時使用。
6. 平台通常都有「Cron Job / 排程任務」功能，可設定每天凌晨自動執行 `npm run backup`，將 `data/db.json` 備份一份到 `data/backups/`（程式已內建此腳本，見下方「備份機制」）。若想備份到診所外部（例如 Email 或雲端硬碟），可請人協助加裝一個小工具，把 `data/backups/` 內的檔案定期上傳到 Google Drive 或 Dropbox。

### 方案 B：先在診所內網路運作（零成本、免部署，但無法從診所外遠端存取）

若暫時只需要「診所內」不同手機/電腦（同一個 Wi-Fi）都能操作，不需要對外網路：

1. 在診所一台常開的電腦上執行 `npm start`。
2. 該電腦區網 IP（例如 `192.168.1.10`）+ Port 3000，診所內其他手機/電腦連同一個 Wi-Fi，瀏覽器輸入 `http://192.168.1.10:3000` 即可使用。
3. 缺點：離開診所 Wi-Fi 無法存取；電腦關機系統就停止；沒有雲端自動備份，需仰賴「備份機制」章節的本機排程。

之後若要延伸到「診所外也能遠端操作」，再升級到方案 A 即可，程式碼完全相同、不需要重寫。

### 方案 C（推薦，單機使用）：打包成 Windows 桌面應用程式（Electron）

像安裝一般 Windows 軟體一樣，雙擊安裝檔、Next 幾次就完成，桌面會有一個圖示，點開就是一個正常的應用程式視窗，關閉視窗會縮到工作列背景常駐、開機自動啟動。

**打包（在任何一台電腦上執行一次即可，例如開發者的 Mac，不需要在 Windows 上做）：**
```bash
npm run build:electron
```
會在 `electron/dist/` 產生一個「復健科自費療程預約系統 Setup 1.0.0.exe」安裝檔（約 75MB，內含完整 Chromium + Node.js 執行環境）。這個指令會自動把最新的 `server/`、`public/` 同步進 `electron/` 資料夾再打包，不需要手動複製檔案。

> 這個打包流程除了確認產出合法的 Windows 安裝檔之外，我還進一步用 Wine（macOS 上模擬 Windows 執行環境的工具）實際執行了打包出來的程式，確認登入、建立資料庫種子資料、讀取網頁前端檔案都正常運作——比 pkg 那條路的驗證更完整一些，但畢竟不是真正的 Windows，仍建議第一次安裝後實際確認一下。

**安裝到診所的 Windows 電腦：**
1. 把 `electron/dist/復健科自費療程預約系統 Setup 1.0.0.exe` 複製過去，雙擊執行（會有「未知發布者」的 Windows SmartScreen 提示，這是因為沒有付費的程式碼簽章憑證，點選「其他資訊」→「仍要執行」即可，這與程式安不安全無關）。
2. 安裝精靈跑完後會自動啟動，桌面/開始選單會有捷徑。
3. 開啟後是一個正常視窗，網址是 `http://localhost:3000`。
4. 關閉視窗只是縮到工作列（右下角系統列圖示），程式仍在背景執行；要真的結束請對系統列圖示點右鍵選「結束」。
5. 之後每次開機會自動啟動（安裝時就設定好了），開機後预设是安靜留在工作列，不會自動跳出視窗；要開啟主畫面，點系統列圖示即可。
6. 資料庫、備份都存在 Windows 的使用者資料目錄下（`%APPDATA%\rehab-booking-desktop`），跟安裝程式本體分開，重新安裝新版本不會動到這裡的資料。
7. 換到新電腦時，把新的安裝檔複製過去重新執行一次即可，跟安裝任何一般軟體一樣。

#### 同一個區網內兩台電腦共用同一份資料

伺服器預設會監聽電腦的所有網路介面（不只本機），所以如果同一個 Wi-Fi / 路由器底下還有第二台電腦也想用**同一份資料**（例如同時看同一份預約表），不需要另外同步——直接讓其中一台當「主機」（照上面步驟安裝、開著），另一台完全不需要安裝任何東西，開瀏覽器輸入主機的網址即可，兩邊看到的是同一份即時資料，不會有衝突問題。

主機的網址可以到「內部維護 → 版本資訊」頁面查看（會列出所有偵測到的區網 IP，例如 `http://192.168.1.10:3000`）。第一次有其他電腦連進來時，Windows 可能會跳出「Windows 防火牆已封鎖此應用程式的部分功能」的提示，點選「允許存取」（尤其是「私人網路」那個選項）即可，這是一次性的、不需要系統管理員權限的一般使用者提示。

這個方法只適合「同一個區網」的情境；如果兩台電腦不在同一個網路（例如一台在家、一台在診所），就沒辦法用這個方式，需要考慮雲端部署（方案 A）或雲端同步硬碟（OneDrive 等，但要注意兩邊不能同時操作，否則可能造成資料衝突）。

### 方案 D（進階，需要多裝置連線）：打包成不需要 Node.js 的獨立執行檔（pkg）

如果診所可能常常換電腦、或想要「像安裝一般軟體一樣，裝完就能用」，可以把整個系統打包成一個**不需要安裝 Node.js** 的獨立執行檔，之後要換到新電腦，只要複製一個資料夾、對著 `install.bat` 按右鍵「以系統管理員身分執行」即可，不需要重跑 `npm install` 等任何指令。

**打包（在任何一台有裝 Node.js 的電腦上執行一次即可，例如開發者的電腦，不需要在 Windows 上做）：**
```bash
npm install
npm run build:win
```
會在 `dist/RehabBookingSystem.exe` 產生一個約 60~70MB、內含完整 Node.js 執行環境的獨立執行檔。**這個執行檔只包含後端程式碼，不包含網頁前端檔案**（`public/` 資料夾，見下方說明），把 exe 和整個 `public/` 資料夾都複製到 `installer/` 資料夾（與 `install.bat` 同一層），整個 `installer/` 資料夾就是可以拿去安裝的完整套件。

> `build:win` 指令裡的 `--no-bytecode --public --public-packages "*"` 不是可有可無的參數：如果在非 Windows 電腦上（例如 Mac）跨平台打包給 Windows 用，pkg 預設會內嵌 V8 bytecode 快取，但 bytecode 是跟編譯它的那台機器的 V8 版本綁定的，跨平台會不相容，執行時會直接報錯關閉（`V8 rejected the bytecode cache`）。這幾個參數會讓 pkg 改成內嵌純 JavaScript 原始碼而不是 bytecode，避免這個問題，請勿拿掉。

> `public/` 資料夾（登入頁、排程總覽等網頁前端 HTML/CSS/JS）刻意**不**打包進 exe 裡面，而是跟 exe 放在同一層、由執行時讀取。原本試過用 pkg 的資源內嵌功能把 `public/` 包進執行檔內，但在實際 Windows 執行時找不到檔案（`Cannot GET /`），改成這樣可以直接用檔案總管確認檔案有沒有放對，較容易排查問題。

**安裝到診所的 Windows 電腦：**
1. 把 `installer/` 整個資料夾複製過去（隨意位置，例如桌面）。
2. 對 `install.bat` 點右鍵 →「以系統管理員身分執行」（直接雙擊也會跳出 UAC 要求權限）。
3. 腳本會自動：把執行檔與 `public/` 資料夾安裝到 `Program Files\RehabBookingSystem`、開防火牆 port 3000、設定「工作排程器」在開機時以 SYSTEM 身分自動啟動（不需登入任何帳號，效果等同背景服務，程式意外中斷也會自動重啟），並立即啟動一次。
4. 完成後畫面會顯示存取網址；之後每次開機都會自動啟動，換到別台電腦時，同一份 `installer/` 資料夾複製過去重新安裝一次即可。
5. 移除時對 `uninstall.bat` 點右鍵「以系統管理員身分執行」（不會刪除病患資料，資料庫與備份會保留在安裝資料夾內）。
6. 這個獨立執行檔預設就會啟用 HTTPS（自簽憑證，見下方說明）並每天自動備份 `data/db.json`，不需要另外設定工作排程器或 `HTTPS` 環境變數。

> 這個打包/安裝流程我已經在本機完整建置並驗證過（確認產出的是合法 Windows 執行檔、程式邏輯在模擬打包環境下正確把資料夾放在執行檔旁邊、HTTPS 預設開啟等），但因為目前環境沒有 Windows 可以直接執行 .exe，實際在 Windows 上跑起來的最後一哩路還沒有機會真的測過，第一次安裝後請確認一下是否正常，有問題隨時跟我說。

#### 在 Windows 電腦上安裝為「背景服務」常駐執行（進階／原始碼部署適用）

若不想打包成獨立執行檔，想直接用原始碼 + Node.js 執行（例如開發中需要常常改程式碼），也可以用下面這個方式安裝為服務：

只用 `npm start` 執行的話，一旦關掉那個命令視窗、登出帳號、或電腦重開機，系統就會停止。若要讓這台 Windows 電腦真正當作診所內的常駐伺服器（開機自動啟動、不用登入帳號、程式意外中斷也會自動重啟），可以把它安裝成 Windows 服務：

1. 到 [nodejs.org](https://nodejs.org) 下載安裝 Node.js LTS 版（Windows Installer）。
2. 把整個 `rehab-booking` 專案資料夾複製到這台電腦（例如 `C:\rehab-booking`）。
3. 以**系統管理員身分**開啟 PowerShell，切換到專案資料夾，執行：
   ```powershell
   npm install
   npm run install-windows-service
   ```
   這會把系統安裝成一個名為 `RehabBookingSystem` 的 Windows 服務並立即啟動。之後每次開機都會自動啟動，不需要登入任何帳號、也不需要開著命令視窗；若程式意外當掉，Windows 也會自動重啟它。此腳本預設會開啟 HTTPS（見下方「HTTPS / 自簽憑證」）。
4. 可到「服務」管理視窗（執行 `services.msc`）找到 `RehabBookingSystem`，確認狀態為「執行中」，也可以在此手動啟動/停止。
5. 開啟「Windows Defender 防火牆」，允許 TCP 3000 連入，或用系統管理員 PowerShell 執行：
   ```powershell
   netsh advfirewall firewall add rule name="RehabBooking" dir=in action=allow protocol=TCP localport=3000
   ```
6. 執行 `ipconfig` 找出這台電腦的區網 IPv4 位址（例如 `192.168.1.10`），診所內其他手機/電腦連同一個 Wi-Fi，瀏覽器輸入 `https://192.168.1.10:3000`（注意是 **https**）即可使用。建議到路由器設定，把這台電腦的 IP 設為「DHCP 保留位址」，避免哪天 IP 換掉導致大家連不上、也導致憑證要重新產生。
7. 若之後要移除服務，一樣以系統管理員身分執行：
   ```powershell
   npm run uninstall-windows-service
   ```
8. 資料庫檔案 `data/db.json` 仍在本機，建議搭配下方「備份機制」，用 Windows「工作排程器」每天定時執行 `npm run backup`。

#### HTTPS / 自簽憑證（為什麼瀏覽器一開始會顯示「不安全」）

只用 `http://` 存取時，瀏覽器一定會顯示「不安全」，因為連線完全沒有加密，尤其這個系統有登入密碼、病患資料，建議加密。

本系統內建自動產生「自簽憑證」的功能：只要啟動時設定環境變數 `HTTPS=true`（`npm run install-windows-service` 已經預設帶入），伺服器會在第一次啟動時自動於 `data/certs/` 產生一組憑證，並改用 `https://` 提供服務。之後改用瀏覽器輸入 `https://192.168.1.10:3000` 存取即可讓連線加密。

因為這不是由公開信任機構（如 Let's Encrypt）簽發的憑證，瀏覽器**第一次連線仍會顯示一次性警告**（例如「您的連線不是私人連線」），這是正常現象，點選「進階」→「繼續前往 xxx（不安全）」即可，之後同一台瀏覽器通常不會再提醒；跟原本 `http://` 那種「完全不加密」的不安全警告不同，這裡連線本身已經是加密的，只是憑證身分未經第三方驗證。若要讓所有裝置完全不跳出警告（呈現正常的鎖頭圖示），需要額外把 `data/certs/cert.pem` 安裝到診所內每台裝置的「受信任的憑證授權單位」，此步驟較繁瑣、非必要。

若之前已經先用舊版腳本安裝過服務（沒有 HTTPS），要補上這個功能，需要：
```powershell
npm run uninstall-windows-service
npm install
npm run install-windows-service
```

若改用方案 A 部署到 Zeabur / Render 等雲端平台，不需要開啟這個選項——平台本身就會提供公開信任的 HTTPS 憑證，不會有警告。

## 備份機制

程式內建簡易備份腳本：

```bash
npm run backup
```

會將 `data/db.json` 複製一份加上時間戳記存到 `data/backups/`，並自動只保留最近 30 份。建議：

- **本機使用**：用作業系統排程器（Windows「工作排程器」／Mac、Linux 用 `cron`）每天自動執行一次此指令。
- **雲端部署（方案 A）**：用 Zeabur / Render 的 Cron Job 功能，每天排程執行 `npm run backup`。
- 若要更保險，可再搭配一個小腳本把 `data/backups/` 內的檔案上傳到雲端硬碟（Google Drive、Dropbox 皆有簡易 CLI 工具），達成「異地備份」，未來有需要我可以協助加上這段自動化。

## 進階：升級為正式資料庫（建議在正式上線、資料量變大或多分店時考慮）

目前的 JSON 檔案資料層適合單一伺服器示範與中小量使用。若診所擴大規模或希望有更強的雲端自動備份、多節點高可用性，建議之後升級：

- 改用 **Supabase**（基於 PostgreSQL，內建每日自動備份、可視化管理介面）或 **Neon / Railway Postgres**。
- 只需要把 `server/db.js` 的讀寫邏輯換成資料庫查詢，其餘路由與前端幾乎不需更動，屬於局部性的升級，不需要重寫整個系統。
- 屆時也可以加上更完整的權限管理（例如：櫃檯人員、執行人員、管理者不同權限層級）。

如果之後要做這個升級，可以直接請我協助。
